# Localization (i18n)

evitaLab uses the [Vue i18n](https://vue-i18n.intlify.dev/) plugin (Composition API mode,
configured in `src/vue-plugins/i18n.ts`). Currently the only locale is English
(`SupportedLocale.En`); all messages live in a single catalog:

```
src/modules/i18n/en.json
```

## Rules

- **Every user-facing string** (labels, buttons, tooltips, notifications, validation messages,
  placeholders) must go through i18n. No hardcoded English in templates or services.
- Keys are camelCase and **namespaced by module/feature** — top-level keys include `app`, `common`,
  `panel`, `welcomeScreen`, `tab`, `tabShare`, `command`, `explorer`, `keymapViewer`,
  `entityViewer`, `errorViewer`, `evitaQLConsole`, `graphQLConsole`, `historyComponent`,
  `resultVisualizer`, `schemaViewer`, `serverViewer`, `backupViewer`, `taskViewer`, `jfrViewer`,
  `serverFileViewer`, `trafficViewer`, `mutationHistoryViewer`, `relationViewer`.
- Reuse `common.*` for generic wording (buttons like `common.button.cancel`, placeholders like
  `common.placeholder.null`) before adding new keys.
- A conventional sub-structure inside a feature namespace: `button.*`, `notification.*`,
  `placeholder.*`, plus feature-specific groups. Follow the structure that already exists in the
  namespace you are editing.
- Keymap `Command` enum values double as i18n key parts — every command must have a localization
  under `command.*`.

## Usage

In components:

```ts
import { useI18n } from 'vue-i18n'

const { t } = useI18n()
```

```html
<VBtn>{{ t('common.button.cancel') }}</VBtn>
```

With parameters (named interpolation):

```ts
await toaster.success(t('explorer.catalog.notification.catalogCreated', { catalogName }))
```

Outside components (services), import the global instance:

```ts
import { i18n } from '@/vue-plugins/i18n'

const title: string = i18n.global.t('...')
```

## Adding a new locale

Add the locale to `SupportedLocale`, provide a full message JSON next to `en.json`, and register it
in `createI18n` messages — the message schema is typed against `en.json`, so missing keys are
caught at compile time.
